## 복습

### 속성

- 기초속성
    - 원래 가지고 있는 속성, 현업에서 기본적으로 사용되는 속성
- 추출속성
    - 기초 속성으로부터 가공처리(계산)을 통해 얻어질 수 있는 속성
    - 자료의 중복성 및 무결성 확보를 위해 최소화
- 설계 속성
    - 실제로 존재하지는 않으나 시스템의 효율성을 도모하기 위해 설계자가 임의로 부여하는 속성

### 키

- 후보키
    - 중복 X
    - Null 값을 갖지 않는 것
- 기본키
    - 후보키 대표
- 대체키
    - 후보키 중에서 기본키로 선정되지 않은 속성
- 복합키
    - 둘 이상의 칼럼을 묶음
    - ex)
        - 주문 상세 → 한 주문에서 같은 상품은 1번만 들어
        - 수강신청 → student_id + course_id → 중복 불가
        - 좋아요 → user_id + post_id → 한 사람이 한 번만 좋아요
    - 장점
        - 데이터 의미가 있음: 데이터 자체가 식별자
        - 중복 방지 자동: PK 자체가 제약조건
        - 추가 컬럼 필요 없음: 별도의 ID 컬럼 없이 설계 가능
        - 정규화에 충실: 관계형 DB 설계 원칙에 부합
    - 단점
        - FK 전파 문제: 다른 테이블도 복잡해짐
        - JOIN 복잡
        - PK 길어짐: 인덱스 커짐 → 성능 영향
        - 변경 어려움: 키 값 변경 거의 불가능
    - 추천하는 경우
        - 관계 자체가 키인 경우
        - 중간 테이블(M:N)
        - 변경 가능성 없음
- 순번키
    - 의미 없는 자동 증가 값
    - ex) board_id, user_id, log_id
    - 장점
        - 단순
        - JOIN 쉬움
        - 성능 좋음(인덱스 작음)
        - FK 관리 쉬움
        - 확장성 좋음
    - 단점
        - 데이터 의미 없음
        - 중복 방지 별도 필요
        - 정규화 약해짐
    - 추천하는 경우
        - 대부분의 테이블
        - 변경 가능성 있음
        - 확장 고려

→ 실무에서 많이 쓰는 패턴: 순번키 + UNIQUE 복합키

```sql
ORDER_ITEM
-----------
order_item_id   PK
order_id
product_id

UNIQUE(order_id, product_id)
```

### 데이터 모델링

- 개념적 데이터 모델링
    - 업무에서 필요한 핵심 데이터와 데이터 간 관계를 추상적으로 표현
    - 목적
        - 업무 구조 이해
        - 핵심 엔티티 도출
        - 데이터 관계 정의
    - 특징
        - 업무 중심
        - 추상적 표현
        - 기술 요소 제외
        - DBMS 비의존적
    - 표현 대상
        - 엔티티
        - 관계
- 논리적 데이터 모델링
    - 개념적 모델을 기반으로 데이터 구조를 테이블 형태로 구체화하는 모델링 단계
    - 목적
        - 데이터 구조 설계
        - 정규화 수행
        - 무결성 정의
    - 특징
        - 테이블 구조 중심
        - PK/FK 정의
        - 속성 정의
        - 정규화 반영
        - DBMS 비의존적
    - 표현 대상
        - 엔티티
        - 속성
        - PK/FK
        - 관계
        - 정규화 구조
- 물리적 데이터 모델링
    - 논리적 모델을 실제 DBMS 환경에 맞게 구현 가능한 형태로 변환하는 모델링 단계
    - 목적
        - 실제 DB 구현
        - 저장 구조 설계
        - 성능 최적화
    - 특징
        - DBMS 의존적
        - 데이터 타입 정의
        - 인덱스 설계
        - 성능 고려
    - 표현 대상
        - 테이블
        - 컬럼 타입
        - 인덱스
        - 제약조건
        - 파티션
        - 시퀀스

### 슈퍼/서브타입

- 슈퍼 타입
    - 공통 속성을 가진 상위 개념 엔티티
- 서브 타입
    - 슈퍼 타입을 상속받은 하위 개념 엔티티

### 관계

- 배타적 관계(Exclusive)
    - 하나의 서브타입에만 속함
    - 컬럼 하나로만 표현 가능
- 포함 관계(Inclusive)
    - 여러 서브타입에 동시에 속할 수 있음
    - 컬럼이 모두 필요(Y/N)
- 재귀적 관계(Recursive Relationship)
    - 하나의 엔티티가 자기 자신과 관계를 맺는 구조
        - 계층 구조를 표현할 때 사용
        - 최상위는 FK=NULL
    - 같은 테이블 안에서 PK → FK가 다시 같은 테이블의 PK를 참조
    - ex) 조직도, 카테고리, BOM, 메뉴, 지역
    - 재귀 속도 느림
        - 재귀 CTE(Common Table Expression)는 depth만큼 테이블을 반복 스캔
        - Redis 캐싱, Closure Table 사용

## 수업 정리

### 정규화(Normalization)

- 실세계에서 발생하는 데이터를 수학적인 방법에 의해 구조화시켜 체계적으로 관리할 수 있도록 한 이론
- 데이터 중복을 줄이고 무결성을 유지하기 위해 테이블을 분리하는 과정
- 필요성
    - 엔티티를 구성하는 속성 간의 중복을 제거하여 데이터베이스를 최적화
    - 속성 간의 함수 종속성에 의해 발생하는 이상 현상을 제거
        
        
        | **이상현상** | **내용** |
        | --- | --- |
        | 입력이상 | 데이터 입력 시 필요없는 속성까지 입력해야 하는 현상 |
        | 수정이상 | 데이터 수정시 원하지 않는 데이터까지 수정되는 현상 |
        | 삭제이상 | 데이터 삭제 시 필요한 데이터까지 삭제되는 현상 |
- 정규화 종류
    
    
    | **정규화 종류** | 요약 | **내용** | **함수종속성** |
    | --- | --- | --- | --- |
    | 1차 정규화 | 반복 컬럼 제거 | 모든 속성은 원자값을 가짐 
    복수의 속성 값을 갖는 속성을 분리 |  |
    | 2차 정규화 | 복합키 일부에만 종속되는 컬럼 제거 | 주식별자에 종속적이지 않은 속성의 분리         
    부분 종속 속성을 분리 | 부분함수종속성 |
    | 3차 정규화 | 이행 종속 제거 | 속성에 종속적인 속성의 분리 
    이전 종속 속성의 분리 | 이행함수종속성 |
    | 보이스-코드 정규화 |  | 다수의 주식별자 분리 |  |
    | 4차 정규화 |  | 속성간의 다중종속성 제거 | 다중종속성 |
    | 5차 정규화 |  | Join 종속성 제거 | Join 종속성 |
- 장점
    - 중복 감소
    - 무결성 향상
    - 유지보수 쉬움
    - 구조 안정성
- 단점
    - JOIN 증가
    - 성능 저하 가능
    - 구조 복잡

### 반정규화(Denormalization)

- 조회 성능 향상을 위해 일부 중복을 허용
    - 근거가 있어야 함
- 컬럼에 의한 반정규화
    - 중복 컬럼 추가
    - 파생 컬럼 추가
        - ex) 계산 결과 저장
    - 이력 컬럼 / 이력 테이블 추가
        - 감사, 추적 용도
    - PK 분리 컬럼 반정규화
        - 복합 PK를 따로 저장
    - 데이터 복구를 위한 컬럼 추가
- 테이블 반정규화
    - 관계 병합(슈퍼 타입, 서브 타입)
        
        ```sql
        -- 기존
        EMPLOYEE
        REGULAR_EMPLOYEE
        CONTRACT_EMPLOYEE
        ```
        
        ```sql
        -- 병합
        EMPLOYEE
        - employee_type
        - salary
        - contract_end_date
        ```
        
    - 테이블 분할
        - 수평 분할: 행 기준 분리
            - ex) 2024 주문, 2025 주문
        - 수직 분할: 컬럼 기준 분리
            - 회원 기본 정보, 회원 대용량 프로필
    - 중복 테이블, 통계 테이블, 이력 테이블, 부분 테이블 추가
- 장점
    - 조회 성능 향상
    - 집계 속도 향상
    - 화면 응답 속도 향상
- 단점
    - 데이터 중복
    - 무결성 위험
    - 수정 복잡
