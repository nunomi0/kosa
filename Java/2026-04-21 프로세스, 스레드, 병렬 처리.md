## 프로세스(Process)

- 실행 중인 프로그램
- 독립된 메모리 공간을 가짐
    - Code, Heap, Stack 전부 분리

## 스레드(Thread)

- 프로세스 내부의 실행 흐름 단위
- 하나의 프로세스는 여러 스레드를 가질 수 있음

```java
           start()
   ┌───────────────┐
   ▼               │
 [NEW] ─────────▶ [RUNNABLE] ────────────────┐
                      │                     │
                      │                     │
          ┌───────────┼───────────┐         │
          ▼           ▼           ▼         │
     [BLOCKED]   [WAITING]   [TIMED_WAITING]
          │           │           │
          │           │           │
   lock 획득   notify / 종료    시간 만료
          │           │           │
          └───────────┴───────────┘
                      │
                      ▼
                 [RUNNABLE]
                      │
                      │ run() 종료
                      ▼
                [TERMINATED]
```

## 병렬 처리(Parallel Processing)

- 여러 작업을 물리적으로 동시에 수행하는 것 → 전체 처리 속도를 높임

### 멀티 프로세싱 (Multiprocessing)

- 여러 개의 프로세스를 생성해서 작업을 나눠 처리하는 것
- 프로세스 = 독립된 메모리 공간
    - 메모리 서로 공유 불가 → IPC (Pipe, Queue, Shared Memory) 필요
- 장점: 안정성이 높음
- 단점: 생성 비용 큼
- ex) CPU-bound 작업
    - 프로그램 실행 시간의 대부분이 CPU 연산 속도에 의해 결정되는 작업
        - 수치 계산 (행렬 연산, 통계 계산)
        - 이미지/영상 처리 (픽셀 단위 연산)
        - 암호화, 해싱 (SHA, AES)
        - 머신러닝 학습
        - 알고리즘 문제 (정렬, 그래프 탐색, DP)

### 멀티 스레딩 (Multithreading)

- 하나의 프로세스 안에서 여러 스레드로 작업을 나눠 처리
- 스레드는 같은 메모리 공간(heap)을 공유하므로 데이터 공유가 쉬움
- 장점: 생성 비용 적음
- 단점: 동기화 문제 발생 (race condition → Lock, synchronized 필요)
- ex) I/O bound 작업
    - 네트워크 요청 (HTTP API 호출)
    - 데이터베이스 쿼리
    - 파일 읽기/쓰기 (디스크 I/O)
    - 사용자 입력 대기

### 스레드 생성 방법

1. Thread 클래스 상속
    - 스레드 자체를 정의 → 실행 주체 + 작업 둘 다 포함하는 형태
        - 매번 새 객체 만들어야 함 → 재사용이 어려움
        - Thread는 한 번 실행하면 상태가 `TERMINATED`로 끝남 → 다시 `start()` 불가
    
    ```java
    class MyThread extends Thread {
        public void run() {
            System.out.println("Thread 실행");
        }
    }
    
    new MyThread().start();
    ```
    
2. Runnable 구현
    - 작업과 스레드 분리 → 같은 task를 여러 번 실행 가능
    - 실제 스레드는 `Thread`가 생성
    
    ```java
    class MyTask implements Runnable {
        public void run() {
            System.out.println("Thread 실행");
        }
    }
    
    new Thread(new MyTask()).start();
    ```
    

### 멀티 코어를 쓰면 무조건 빨라질까?

- 다음과 같은 상황에서는 오히려 일반 스트림(Sequential)보다 느려질 수 있음
    1. 데이터가 너무 적을 때 → 코어를 나누는 비용이 더 큼
    2. 요소당 처리 비용이 낮을 때 → 코어를 나누는 비용이 더 큼
    3. 공유 자원이 경합하는 경우 → 병목 현상 발생 가능

## CPU 구조

```java
CPU
 └─ 물리 코어 (Core)
      └─ 논리 프로세서 (Logical Processor)
           └─ 스레드 (Thread)
```

- 논리 프로세서 = 코어 수 × 하이퍼스레딩
- 하이퍼스레딩(Hyter-Threading)
    - 1개의 코어를 2개처럼 보이게 만드는 기술
    - 코어 내부 자원을 쪼개서 동시에 활용
    - 성능 1.2~1.5배 증가
        - 같은 물리 코어(ALU, 캐시) 공유로 충돌 발생하기 때문에 2배보다 적음

## volatile

```java
volatile int count;
```

- 변수 값을 메인 메모리에서 직접 읽고 쓰도록 강제
    - 읽기 → 항상 메인 메모리에서 가져옴
    - 쓰기 → 항상 메인 메모리에 반영
- 필요한 이유
    - 멀티 스레드에서 각 스레드는 변수 값을 CPU 캐시에 복사해서 사용
        - 각 Thread 에서 값이 안 보일 수 있음 → 가시성 문제 발생
- 가시성 보장 / 원자성, 동기화 보장 X
    
    → 상태 체크용으로 사용
