# JDBC

- Java Database Connectivity
- 자바에서 데이터베이스에 접속하고 SQL을 실행하기 위한 표준 API
    - Java Application ↔ Database 연결 기술
- 구조
    - Java Application → JDBC API → JDBC Driver → Oracle
- DB마다 JDBC Driver가 다름
    - Oracle → ojdbc
    - MySQL → mysql-connector
    - MariaDB → mariadb-java-client
- 인터페이스 기반 구조 → 다형성
    - `java.sql` 패키지의 인터페이스를 통해 표준화된 DB 작업 수행
    
    | **객체** | **역할** |
    | --- | --- |
    | DriverManager | Driver 관리 및 DB 연결 |
    | Connection | DB 연결 |
    | Statement | SQL 실행 |
    | PreparedStatement | parameter SQL 실행 |
    | CallableStatement | Procedure 실행 |
    | ResultSet | 조회 결과 저장 |
    - 부모 타입은 같음
        - 어떤 DB를 사용해도 똑같은 코드를 만들 수 있다
        - 결국 자식 객체만 바꾸면 된다

## **JDBC 작업 순서**

### 1. Driver 로딩

- Oracle JDBC Driver를 메모리에 로딩
    - Java가 Oracle과 통신 방법을 알아야 하기 때문

```java
Class.forName("oracle.jdbc.OracleDriver");
```

### 2. DB 연결

- Java ↔ DB 연결 생성
- DB 연결 담당 객체 `Connection` 사용

```java
conn = DriverManager.getConnection(
    "jdbc:oracle:thin:@localhost:1521/XEPDB1",
    "KOSA",
    "1004"
);
```

- Thin Driver
    - Oracle이 제공하는 JDBC Driver 방식 중 하나
    - 과거에는 OCI Driver 사용
    
    | **특징** | **설명** |
    | --- | --- |
    | Java 기반 | Pure Java |
    | Oracle Client 불필요 | jar만 있으면 됨 |
    | 설치 쉬움 | 실무 표준 |
    | 플랫폼 독립 | 어디서나 실행 |

### 3. SQL 생성

- DB 서버에 전달할 SQL 작성
- SQL 실행 객체 사용
    - `Statement`
    - `PreparedStatement`
        
        ```java
        String sql =
            "select * from emp where empno = ?";
        
        PreparedStatement pstmt =
            conn.prepareStatement(sql);
        ```
        
    - `CallableStatement`

### 4. SQL 실행

- DB 서버에 SQL 전달 후 실행
- `executeQuery()`
    - SELECT 전용
    - ResultSet 반환
- `executeUpdate()`
    - INSERT, UPDATE, DELETE
    - 영향받은 행 개수 반환

### 5. 결과 처리

- SELECT 결과를 `ResultSet` 객체로 반환
    - DB 조회 결과를 row 단위로 읽기 위한 객체
    - 
    
    ```java
    while(rs.next()) {
    	System.out.println(
    	    rs.getInt("empno") + " / " +
    	    rs.getString("ename") + " / " +
    	    rs.getInt("sal")
    	);
    }
    ```
    

### 6. 자원 해제

- DB 연결은 비싼 자원 → 해제하지 않으면 다음과 같은 문제 발생
    - 메모리 누수
    - Connection 부족
    - 서버 장애
- `ResultSet`→ `Statement`→ `Connection` 순서로 닫기

```java
rs.close();
pstmt.close();
conn.close();
```

### 전체 코드

```java
import java.sql.*;

public class JdbcExample {

    public static void main(String[] args) {

        Connection conn = null;
        PreparedStatement pstmt = null;
        ResultSet rs = null;

        try {

            // 1. Driver 로딩
            Class.forName("oracle.jdbc.OracleDriver");

            // 2. DB 연결
            conn = DriverManager.getConnection(
                "jdbc:oracle:thin:@localhost:1521/XEPDB1",
                "KOSA",
                "1004"
            );

            // 3. SQL 생성
            String sql =
                "select empno, ename, sal from emp where deptno = ?";

            pstmt = conn.prepareStatement(sql);

            pstmt.setInt(1, 20);

            // 4. SQL 실행
            rs = pstmt.executeQuery();

            // 5. 결과 처리
            while(rs.next()) {

                System.out.println(
                    rs.getInt("empno") + " / " +
                    rs.getString("ename") + " / " +
                    rs.getInt("sal")
                );
            }

        } catch(Exception e) {

            e.printStackTrace();

        } finally {

            // 6. 자원 해제
            try {

                if(rs != null) rs.close();
                if(pstmt != null) pstmt.close();
                if(conn != null) conn.close();

            } catch(Exception e) {
                e.printStackTrace();
            }
        }
    }
}
```

## JDBC 주요 객체

```java
DriverManager
      ↓
Connection
      ↓
Statement / PreparedStatement / CallableStatement
      ↓
ResultSet
```

### 1. DriverManager

- DB Driver 관리 객체

```java
Connection conn =
    DriverManager.getConnection(
        url,
        id,
        pw
    );
```

### 2. Connection

- DB 연결 객체

| **작업** | **메서드** |
| --- | --- |
| Statement 생성 | createStatement() |
| PreparedStatement 생성 | prepareStatement() |
| Transaction 제어 | commit(), rollback() |
| 자동 commit 설정 | setAutoCommit() |
| 연결 종료 | close() |

```java
conn.commit();
conn.rollback();
conn.close();
```

### 3-1. Statement

- 기본 SQL 실행 객체
    - 문자열 SQL 실행
- SQL 문자열을 실행 시점마다 전달하는 방식 (매번 컴파일 수행)

```java
Statement stmt = conn.createStatement();
ResultSet rs = stmt.executeQuery(sql);
```

### 3-2. PreparedStatement

- parameter SQL 실행
- SQL 사전 컴파일 가능
    - 미리 SQL문이 셋팅된 Statement가 DB에 전송되어 컴파일된 뒤, `?` 자리에 값만 나중에 바인딩해서 실행하는 방식
- 반복적인 SQL문을 사용할 경우 더 빠름
- DB 컬럼 타입과 상관없이 `?` 하나로 표시할 수 있어서 개발자 혼동 방지
- SQL Injection 방지에 유리
- SQL과 파라미터가 분리되어 가독성과 유지보수성이 좋다
- SQL문마다 객체를 각각 생성해야 하므로 재사용성은 떨어짐
- 테이블명, 컬럼명, 시퀀스명 같은 뼈대는 `?`로 표시 불가
    - 그래서 보통 DDL문에서는 사용하지 않음

```java
String sql = "select * from emp where empno = ?";
PreparedStatement pstmt = conn.prepareStatement(sql);
```

### 3-3. CallableStatement

- Procedure 호출 객체
    - JDBC에서 DB의 프로시저를 호출해야 할 때 사용
    - Stored Procedure 실행
- IN parameter / OUT parameter 가능
- `prepareCall()`로 생성

```java
CallableStatement cstmt =
    conn.prepareCall(
        "{call usp_insert_emp(?,?,?)}"
    );
```

```java
cstmt.registerOutParameter(
    2,
    Types.VARCHAR
);
```

### 4. ResultSet

- 조회 결과 저장 객체
    - DB 서버 쪽 결과를 row 단위로 읽음
- ResultSet 객체는 자바 애플리케이션의 JVM 메모리에 생성
    - 실제 조회 데이터의 원천은 DB 서버
        - JDBC Driver가 필요한 만큼 가져와서 읽는 구조

```java
ResultSet rs = pstmt.executeQuery();
```

- ResultSet 커서 이동
    - JDBC 2.0부터는 ResultSet 커서를 원하는 위치로 이동할 수 있음
        - Cursor: 현재 어디를 읽고 있는지 가리키는 포인터
    - 주요 메서드
        - `next()` : 커서를 한 칸 내림
        - `previous()` : 커서를 한 칸 올림
        - `beforeFirst()` : BOF 위치로 이동
        - `afterLast()` : EOF 위치로 이동
    - 기본 ResultSet 상태 → `TYPE_FORWARD_ONLY` 모드
        - 한 방향 스트림 방식
        - 앞으로만 이동 가능
            - rs.next()
        - `createStatement()` 시 `TYPE_SCROLL_INSENSITIVE` 옵션을 주면 스크롤 가능한 ResultSet 생성 가능
            - rs.next(), rs.previous(), rs.beforeFirst(), rs.afterLast() 사용 가능
        
        ```java
        Statement stmt =
            conn.createStatement(
                ResultSet.TYPE_SCROLL_INSENSITIVE,
                ResultSet.CONCUR_READ_ONLY
            );
        ```
        
        - `TYPE_SCROLL_INSENSITIVE`
            - 스크롤 가능한 결과 집합
        - `CONCUR_READ_ONLY`
            - 읽기 전용 결과 집합

## Transaction

- 논리적 작업 단위
    - 중간 실패 시 전체 취소 가능해야 함
- `Connection` 객체 기본값: `autoCommit=true`
    - SQL 실행 시마다 자동 `commit()`
- 수동 처리
    
    ```java
    conn.setAutoCommit(false);
    conn.commit();
    conn.rollback();
    ```
